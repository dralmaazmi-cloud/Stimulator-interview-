## المزود والنموذج

- طبقة المزود الوحيدة: `api/_lib/provider.js`.
- الواجهة الموحدة: `complete(prompt, schema, options)` و`transcribe(audio, mime)`.
- المتغير المطلوب: `GEMINI_API_KEY`.
- كل طلب إلى Interactions API يحمل `store: false` (لا يُخزَّن الطلب ولا الاستجابة لدى المزود)، ولا يُستخدم `previous_interaction_id` إطلاقًا.
- شكل الاستجابة الموثق (REST) الذي يقرأه `provider.js`:

```json
{ "status": "completed",
  "usage": { "total_input_tokens": 8, "total_output_tokens": 12, "total_thought_tokens": 0 },
  "steps": [ { "type": "thought" }, { "type": "model_output", "content": [ { "type": "text", "text": "..." } ] } ] }
```

  النص = كل `steps[].content[].text` حيث `type === 'model_output'` و`content.type === 'text'` بالترتيب. `status` غير `completed` → 502 برسالة عربية ثابتة. JSON المنظم يُقتطع من أول `{` إلى آخر `}` قبل التحليل، دون أي «إصلاح» آخر.
- أخطاء المزود (429 وغيرها) لا تصل رسائلها إلى العميل؛ تُسجَّل في `console.error('[provider]', …)` فقط. 429 → «الخدمة مشغولة حاليًا. حاول بعد دقيقة.» (`AI_RATE_LIMITED`).
- النموذج الافتراضي وقت التنفيذ: `gemini-3.8-flash` عبر Interactions API.
- التبديل الاختياري: `GEMINI_MODEL` و`GEMINI_RETRY_MODEL` و`GEMINI_TRANSCRIBE_MODEL`.
- لا يظهر اسم المزود أو النموذج للمستخدم النهائي.
- لا تستدعِ المزود من `dist/js/`، ولا تضع مفتاحًا أو اسم متغير سري في ملفات العميل.

### تبديل المزود لاحقًا

عدّل `api/_lib/provider.js` فقط مع المحافظة على القيم المعادة:

```js
complete(prompt, schema) => { data, usage, model }
transcribe(audio, mime)  => { transcript, usage, model }
```

ثم شغّل اختبارات المخطط والاقتباسات ومجموعة المعايرة كاملة. لا تغيّر بقية المسارات كي تبدّل المزود.

## محرك التقييم

- التعليمات: `api/_lib/prompts.js`.
- مخطط المخرجات: `api/_lib/schemas.js`.
- التحقق والتطبيع والتشابه: `api/_lib/validation.js`.
- الأوزان والحساب النوعي والرقمي: `api/_lib/scoring.js`.
- نموذج الدليل لا يدخل في تعليمات التقييم؛ يظهر بعد التقرير فقط، ويستخدم الخادم نسخة منه محليًا لاكتشاف النسخ اللفظي.
- كل اقتباس يمر بفحص وجود حرفي بعد تطبيع عربي محدود.
- الاقتباس صالح فقط إذا كان ≥ 3 كلمات بعد التطبيع (أو ≥ 12 حرفًا) ومشمولًا حرفيًا.
- إذا فشل أكثر من 30% من الاقتباسات يعاد الطلب مرة واحدة؛ عدد الطلبات إلى المزود لا يتجاوز 2 في أي مسار (`attempts` في سجل الاستخدام).
- بوابة الثقة (alpha-3): `trusted = failureRate ≤ 0.3 && unverified_criteria ≤ floor(scored_criteria / 2)` حيث `scored_criteria` = المعايير التي أعطاها النموذج درجة > 0 قبل أي تخفيض، و`unverified_criteria` = المعايير الموسومة `unverified`. إذا `scored_criteria = 0` فالتقرير موثوق بدرجة 0 وتصنيف «ضعيفة». غير ذلك عند عدم الثقة: `final_score = null` و`classification = 'غير موثوق'` والعنوان في التقرير «تقييم غير موثوق».
- اكتشاف نسخ نموذج الدليل: تشابه 4-gram ≥ 0.35 **أو** 2-gram ≥ 0.45 **أو** Jaccard كلمات (بعد حذف كلمات ≤ 2 حرف) ≥ 0.6 → تنبيه وتُحد درجة `competency_evidence` إلى 3 من 5.
- النموذج يعطي الدرجات الجزئية فقط؛ الخادم يحسب الدرجة النهائية.

## التسجيل والخصوصية

- الحد: 120 ثانية و4 MB. ترويسة `X-Audio-Duration` إلزامية بكسر عشري (> 0)؛ مدة ≤ 0 → 400 «التسجيل قصير جدًا. سجّل ثانية واحدة على الأقل.»
- الخادم يفحص الترويسة الثنائية للملف (WebM `1A 45 DF A3`، MP4/M4A `ftyp`، MPEG `FF Fx`/`ID3`، WAV `RIFF`) ولا يثق بـ`Content-Type` وحدها؛ عدم التطابق → 415.
- عند فشل التفريغ يحتفظ العميل بالتسجيل في الذاكرة ويعرض «إعادة إرسال التسجيل نفسه»؛ يُحذف عند النجاح أو مغادرة الصفحة.
- التنبيه: بعد 90 ثانية.
- الصيغ: WebM/Opus حيث يتوفر، وMP4 على iOS. الخادم يرسل MP4 إلى المزود بوسم `audio/m4a`.
- الرحلة منفصلة: تسجيل → تفريغ → تصحيح المستخدم → تقييم.
- `api/transcribe.js` يصفّر Buffer بعد الرد.
- لا تحفظ الجلسة الصوت؛ تحفظ النص المصحح والتقرير محليًا فقط.
- `api/_lib/usage.js` لا يسجل نص الإجابة ولا الصوت؛ يسجل `input_tokens` و`output_tokens` و`thought_tokens` و`attempts` فقط.

## حد المعدل

- حدّان معًا (alpha-3): لكل IP (أول قيمة في `x-forwarded-for`) 200/ساعة مشترك بين كل النقاط (`RATE_LIMIT_IP` يغيّره)، ولكل (IP + `X-Client-Id`) حد النقطة: تقييم 40/ساعة (`RATE_LIMIT_EVALUATE` يرفع هذا الحد فقط)، تفريغ 30/ساعة، تقديم الذات 20/ساعة. الطلب 41 بالمعرّف نفسه → 429؛ معرّف آخر من العنوان نفسه يمر حتى يبلغ العنوان 200.
- مخزن KV خادمي للحصص يأتي في المرحلة الثالثة.

## تقديم الذات

- الخوارزمية المحلية هي الأساس والبديل دون إنترنت.
- الترتيب: الماضي → الحاضر → المستقبل.
- الخياران: 60 أو 120 ثانية.
- نقطة `/api/self-intro` تستقبل النص المبني والمدة فقط.
- النسخة المحسنة لا تستبدل النص تلقائيًا؛ يجب أن يعتمدها المستخدم.
- المحاكاة الواقعية والممتدة تستطيع إضافة تقديم الذات وتقييمه بمعايير مستقلة.
- التعديل اليدوي على نص المسودة يُحفظ تلقائيًا (500ms) مع علم `edited_manually`، ويُستعاد عند فتح الصفحة؛ «صياغة بديلة» تطلب تأكيدًا قبل استبدال نص معدّل يدويًا.

## الجلسات غير المكتملة

- «حفظ والخروج» يحفظ الجلسة بحالة `in_progress` مع `draft_answer`.
- الاستئناف من بطاقة أعلى إعداد المحاكاة، أو من الرئيسية، أو من سجل الجلسات؛ يعيد نفس السؤال والمسودة.
- بدء جلسة جديدة أثناء وجود جلسة غير مكتملة يطلب تأكيدًا ثم يحذف القديمة.
- إنهاء الجلسة يحوّل السجل نفسه إلى `completed`؛ لا تبقى نسخة `in_progress`.
- التقرير المحفوظ في `#/sessions/<id>` يعرض الملخص ثم التقرير الكامل لكل إجابة (المعايير والاقتباسات) داخل `details.saved-report`، وتُفتح كلها تلقائيًا عند الطباعة.

## ما يجب اختباره على iPhone

1. Safari على iOS 17 أو أحدث، ثم نسخة PWA من الشاشة الرئيسية.
2. السماح بالميكروفون وبدء التسجيل وإيقافه.
3. تسجيل قصير وتسجيل يصل إلى حد 120 ثانية.
4. ظهور التفريغ في حقل قابل للتعديل وعدم بدء التقييم تلقائيًا.
5. تصحيح كلمة ثم التأكد أن التقرير يستخدم النص المصحح.
6. الوضعان الفاتح والداكن، زر الرجوع، الطباعة، والعمل دون اتصال للتعلم والبنك.
7. التأكد بصريًا من عدم ظهور `null` أو `undefined` في أي صفحة.
8. تسجيل حتى 121 ثانية: التنبيه عند 90 والإيقاف عند 120.
9. `blob.type` الفعلي يظهر في سجل الخادم كـ`audio/mp4` ويُحوَّل إلى `audio/m4a` ويُقبل من المزود.
10. الطباعة من ملخص الجلسة المحفوظ تنتج PDF يحتوي المعايير.
11. وضع الطيران بعد التثبيت.
