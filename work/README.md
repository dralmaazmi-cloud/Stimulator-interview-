# مدرّب المقابلات القيادية

تطبيق ويب تقدّمي عربي (PWA) للتحضير للمقابلات القيادية، ومحاكاتها نصيًا أو صوتيًا، ثم تحويل النتائج إلى خطة تطوير واضحة. الإصدار الحالي `0.6.0-alpha-10` يحسّن قابلية القراءة في الصفحة الرئيسية، ويفصل إخفاء الهوية عن اكتمال تفاصيل الإجابة، ويجعل تحسين التعريف الشخصي بالذكاء الاصطناعي خيارًا واضحًا، مع الحفاظ على مركز الأسئلة التفاعلي والتقارير الشاملة.

## ما يتضمنه الإصدار

### التحضير للمقابلة

خمس محطات تعليمية مستقلة بلا اختبارات قياس فهم، تليها بطاقة سادسة للتدريب التفاعلي على الأسئلة:

1. افهم المقابلة.
2. بناء الإجابة النموذجية.
3. الكفاءات الثمانية.
4. قيادة المهمة.
5. الجاهزية النهائية.
6. الأسئلة.

تتوفر الطباعة وPDF على مستوى الكفاءة أو الفصل أو دليل التحضير كاملًا، لا بعد كل سؤال. يتضمن المستند غلافًا وفهرسًا وجميع الشروح والأسئلة والإجابات النموذجية بتنسيق A4 اقتصادي، ويعمل محتوى التحضير والأسئلة دون اتصال بعد تثبيت التطبيق وتحميله أول مرة.

### مركز الأسئلة والأسئلة المدمجة في سياقها

- راجع النظام `127` سؤالًا في المصدر الأصلي.
- نُشر `70` سؤالًا لها إجابات نموذجية مكتملة العناصر.
- التوزيع: `56` سؤالًا ضمن الكفاءات، و`12` سؤالًا ضمن مبادئ قيادة المهمة، وسؤالان معرفيان من الدليل في «الجاهزية النهائية».
- أُضيفت `22` إجابة نموذجية من ملف الإجابات الموسّعة، وهي مقسّمة إلى: الموقف، التقييم، الإجراء، والأثر القيادي.
- بقي `dist/data/reference.json` دون تعديل؛ تعيش الإضافات في ملف منفصل قابل للتدقيق.
- تحتوي صفحة الكفاءة ثلاثة خيارات: «فهم الكفاءة»، «كيف تُظهرها»، و«الأسئلة»؛ ولا تظهر الأسئلة قبل اختيار تبويبها.
- يفتح كل سؤال في صفحة مستقلة بأربع مراحل متدرجة: السؤال، المطلوب، بناء الإجابة، والمثال. لا تظهر الإجابة النموذجية إلا بطلب المستخدم.
- يقدّم مركز الأسئلة واجهة رئيسية للاختيار حسب الكفاءة أو نوع السؤال أو قيادة المهمة أو الأسئلة المحفوظة.
- تعرض واجهة التدريب سؤالًا واحدًا واضحًا في كل مرة، مع البحث والتصفية والحفظ وتحديد الإتقان والسحب للتنقل.
- يتوفر كتاب مستقل للأسئلة والإجابات النموذجية، مرتب في عشرة فصول ويشمل الأسئلة السبعين المعتمدة.

توجد نتيجة التدقيق التفصيلية في `dist/data/derived/question-audit.json` و`docs/QUESTION_AUDIT_v0.6.0.md`.

### المحاكاة والتقارير

- أربعة أوضاع: سؤال واحد، محاكاة واقعية، محاكاة ممتدة، ومقابلة كاملة.
- إجابة نصية أو صوتية حتى 120 ثانية، مع مراجعة التفريغ قبل التقييم.
- تقييم STAR-L موثّق باقتباسات حرفية من إجابة المستخدم.
- تقرير لكل إجابة يوضح البنية والمعايير ونقاط القوة والنقص وخطوات التحسين.
- تقرير تجميعي للمقابلة يوضح المتوسط، موثوقية التقييمات، معايير الأداء، تغطية STAR-L، الأداء حسب الكفاءة، الأنماط المتكررة، وأولويات المحاكاة القادمة.
- مقارنة محلية بالجلسة السابقة وطباعة أو تصدير PDF.

### الهوية وتجربة الاستخدام

- صورة أبوظبي من البحر في الصفحة الرئيسية فقط.
- واجهات داخلية هادئة بالأيقونات وألوان بترولي وعاجي وكريمي ورملي.
- صفحة رئيسية مضغوطة لتناسب شاشة iPhone العادية بلا تمرير، مع إبقاء التمرير الآمن للشاشات القصيرة جدًا والخط الكبير.
- شريط سفلي ثابت: الرئيسية، التحضير، المحاكاة، التقارير، المزيد.
- زر رجوع سياقي في أعلى اليمين لكل صفحة داخلية.
- أقسام قراءة تفاعلية بنمط حصري: فتح قسم يطوي القسم السابق تلقائيًا.
- صفحة «المزيد» لتغيير الخلفية واللون وحجم الخط وتباعد السطور والتباين والحركة، وفحص الميكروفون، وتصدير البيانات واستيرادها وحذفها.
- شعار إماراتي معتمد كأيقونة PWA على الهاتف.

## الاستقرار والخصوصية

إصلاحات `0.5.1-alpha-4` محفوظة ومغطاة بالاختبارات:

- يعيد محرك الخدمة المحاولة عند أخطاء 500/502/503/504 وفشل الاتصال، ثم يستخدم نموذجًا احتياطيًا اختياريًا.
- يحفظ التطبيق الإجابة أو التسجيل عند الازدحام ويعرض إعادة الإرسال.
- يمنع تكرار الطلب ويستخدم ميزانية زمنية محددة.
- يحافظ على إضاءة الشاشة أثناء التسجيل والتفريغ والتقييم ومؤقت تقديم الذات عندما يدعم الجهاز ذلك.
- يحفظ مسودة الإجابة عند خروج التطبيق من الواجهة.
- كل طلب إلى المزود يحمل `store: false`، ولا تُحفظ محادثة سابقة لدى المزود.
- لا يسجل الخادم نص الإجابة أو الصوت أو الاستجابة الخام.

## تشغيل محلي

```bash
python3 -m http.server 4173 --directory dist
```

ثم افتح `http://localhost:4173`. خادم الملفات البسيط لا يشغل نقاط `/api`؛ استخدم Vercel أو خادم التدقيق لاختبارها.

```bash
npm run derive
npm test
```

- `derive`: يعيد بناء البيانات المشتقة دون تعديل `reference.json`.
- `test`: يشغّل اختبارات المحتوى والتقييم والصمود وقفل الشاشة دون استهلاك API حقيقي.
- `test:live`: يشغّل المعايرة على نشر تجريبي عند ضبط `PHASE2_BASE_URL`.

## النشر على Vercel

1. ارفع المشروع إلى GitHub.
2. استورده إلى Vercel؛ يحدد `vercel.json` مجلد `dist` للإخراج.
3. أضف `GEMINI_API_KEY` في **Settings → Environment Variables** ثم أعد النشر.
4. افتح `/api/health` وتأكد من ظهور `"configured": true`.
5. اختبر إجابة نصية، ثم تسجيلًا صوتيًا من Safari، ثم من نسخة PWA المثبتة.

المتغيرات الاختيارية:

- `GEMINI_MODEL`: نموذج التقييم الأساسي.
- `GEMINI_RETRY_MODEL`: نموذج إصلاح مخطط التقييم.
- `GEMINI_EVALUATION_FALLBACK_MODEL`: احتياطي التقييم عند الازدحام، وعند انتهاء مهلة النموذج الأساسي إن بقي 20 ثانية على الأقل من ميزانية الطلب.
- `GEMINI_EVALUATION_THINKING_LEVEL` (اختياري): مستوى التفكير لنداءات التقييم عبر `generation_config.thinking_level`؛ القيم `minimal` أو `low` (الافتراضي) أو `medium` أو `high`، و`off` لحذف الحقل إن كان النموذج لا يدعمه.
- `GEMINI_TRANSCRIBE_MODEL`: نموذج التفريغ.
- `GEMINI_TRANSCRIBE_FALLBACK_MODEL`: احتياطي التفريغ عند الازدحام.

لا تضع المفتاح في GitHub أو `dist` أو المحادثات.

## بنية المشروع

```text
api/                         وظائف التقييم والتفريغ والصمود
dist/                        التطبيق المنشور
  assets/images/             صورة الصفحة الرئيسية
  assets/icons/              أيقونات التثبيت
  data/reference.json        المصدر الأصلي غير المعدّل
  data/derived/              الأسئلة المعتمدة والتدقيق والفهارس
  js/                        الواجهة والمحاكاة والتقارير
tests/                       اختبارات المحتوى والمحرك والصمود
audit-harness/               سيناريوهات API وفحوص الواجهة والرحلات
tools/                       بناء البيانات المشتقة
docs/                        تقارير التدقيق والقبول
```

## حالة الاعتماد

النسخة Alpha جاهزة للنشر التجريبي. الاختبارات المحلية وسيناريوهات المزود الوهمي ناجحة. يبقى قبل الإطلاق العام: اختبار بصري ووظيفي على iPhone فعلي، واختبار API حي بالمفتاح، ومراقبة التكلفة والحصص.
