# Educational simplification and explanation

Goal: explanations the target learner understands on first read, that remain true when the learner later meets the full version.

## Process
1. **Start from verified content** (evidence log). Never simplify from memory.
2. **Explain in this order:** plain-language idea, concrete example, then the formal term or formula. Define every term before using it.
3. **Keep it short.** One idea per sentence; one concept per paragraph or screen; prefer active voice; target length for a phone screen.
4. **Pick the device that fits** (patterns and examples in `references/explanation-patterns.md`, read when needed):
   - Concrete example with real numbers or a real case.
   - Analogy, with one line on where it stops working.
   - Step-by-step procedure, numbered.
   - Comparison table for similar or confusable items.
   - Mnemonic or abbreviation only when it maps exactly to the content and is easier than the content itself.
   - Misconception check: "A common mistake is ... because ...".
5. **Accuracy check.** For every simplified statement ask: is it still true, or only true with an unstated condition? If a condition matters, state it. Mark deliberate simplifications ("At this level we ignore ...").
6. **Language.** Match the learner's language. For technical fields taught in Arabic, give the Arabic term with the standard English term once (for example "الرباط الصليبي الأمامي (ACL)"), then keep terminology consistent.

## Output
For each key concept: short explanation, example, optional analogy with its limit, optional mnemonic, common misconception, and source IDs.
